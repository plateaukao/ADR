# NerLan (iOS): cleartext-HTTP podcast feeds wouldn't show art or play

## Problem

The same defect found on Android (see `nerlan-android-cleartext-podcast-playback`) was latent on iOS: a podcast subscribed via its Apple Podcasts URL whose feed serves assets over plain HTTP (reported case: BBC Inside Science) would list episodes but show **no cover art and refuse to play any audio**.

## Root Cause

The feed serves its cover art (`http://ichef.bbci.co.uk/...`) and every audio enclosure (`http://open.live.bbc.co.uk/...`, some of which redirect to a cleartext CDN) over HTTP. iOS App Transport Security was configured with `NSAllowsArbitraryLoads: false`, so the OS blocks all cleartext loads: `AsyncImage` (URLSession) couldn't fetch the cover and `AVPlayer` refused the audio. As on Android, the RSS XML is fetched over HTTPS so the parse and subscription succeed — only the asset loads fail.

A per-domain ATS exception isn't viable because podcast hosts are arbitrary user-supplied domains. A media-only exception (`NSAllowsArbitraryLoadsForMedia`) would unblock `AVPlayer` audio but not the `AsyncImage` cover-art load, leaving the art broken.

## Solution

Set `NSAllowsArbitraryLoads: true` under `NSAppTransportSecurity` in `project.yml` (the xcodegen source of truth, which generates `NerLan/Resources/Info.plist`), then regenerated the project. This covers both the AVPlayer audio and the URLSession/AsyncImage cover art over HTTP. The app is distributed development-signed, so the App Store ATS-justification prompt doesn't apply; the justification ("podcast client loading arbitrary user-supplied feeds") would hold regardless.

Built for device successfully.

## Key Files

- `project.yml` — `NSAppTransportSecurity.NSAllowsArbitraryLoads` flipped to `true`, with a comment explaining the arbitrary-feed rationale.
- `NerLan/Resources/Info.plist` — regenerated by `xcodegen generate` to carry the new key.

## Lessons Learned

- ATS and Android's cleartext policy are the same wall in two costumes; a cleartext-only feed fails identically on both platforms, so a fix on one should prompt a check of the other (this feature mirrors between the two apps).
- Reach for `NSAllowsArbitraryLoads` over `NSAllowsArbitraryLoadsForMedia` when the broken assets include non-media loads (cover art via URLSession) — the media-scoped exception silently leaves images blocked.
- `project.yml` is the source of truth here; edit it and re-run `xcodegen generate` rather than hand-patching the generated `Info.plist`.
